# 性能评测 - 移除 Protocol 包

## 结论

> [!success] 通过
> Provider 路径相对未修改的 Health 控制路径没有出现专项回退，两轮各 1,000 个样本均为 0 错误。毫秒级绝对 p95/p99 同步波动已记录为本机短时负载噪声，不归因于只影响类型所有权的重构。

## 环境与负载模型

- Apache JMeter 5.6.3，复用 [[2026-08-27-1531-performance]] 的测试计划、运行时和本机 loopback 环境。
- 对照值：上一轮已验证的 `protocol + llm` 实现结果。
- 当前实现：移除 `protocol`，Server DTO、Web VO、LLM 领域类型独立维护；HTTP 路由与 JSON 字段未变。
- 路径：`GET /api/health` 作为未修改控制路径，`GET /api/ai/providers` 作为受观测路径。
- 每轮预热：每条路径 5 线程 × 20 次循环，共 100 样本。
- 每轮正式负载：10 线程、1 秒 ramp-up、每线程 100 次循环，每条路径 1,000 样本。
- 因首轮绝对尾延迟出现同步波动，按相同参数追加一次复测；两轮原始数据均保留。

## 指标结果

JMeter Dashboard 的 `pct2ResTime`、`pct3ResTime` 分别为 p95、p99。

| 路径/指标 | 上一实现 | 当前首轮 | 当前复测 |
| --- | ---: | ---: | ---: |
| Health p95 / p99 | 1 / 2 ms | 2 / 5 ms | 4 / 6 ms |
| Provider p95 / p99 | 1 / 2 ms | 2 / 4 ms | 2 / 4 ms |
| Health 吞吐量 | 1137.7 req/s | 1103.8 req/s | 1169.6 req/s |
| Provider 吞吐量 | 1070.7 req/s | 1034.1 req/s | 1107.4 req/s |
| Provider / Health 吞吐比 | 94.11% | 93.69% | 94.68% |
| 两条路径错误率 | 0% | 0% | 0% |

## 判定说明

- 绝对 p95/p99 的百分比越过通用阈值，但基数只有 1–2ms，且未修改的 Health 控制路径波动更大。
- 两轮 Provider p95/p99 均不高于同轮 Health；Provider/Health 吞吐比相对对照仅变化 -0.45% 与 +0.61%，未触发 5% 告警。
- 本次源码变化不改变 Health 路径，也不改变 Provider 的运行时计算、存储或序列化字段；因此没有可归因的专项性能回退。

## 剩余风险

- 1 秒本机微基准对毫秒级调度噪声敏感；需要稳定的长期性能趋势时，应改为持续时间更长、固定环境的 CI 基准。
- 本报告不代表第三方 LLM、OAuth 或 SSE 网络性能；本次未修改这些运行时路径。
