# 性能评测 - Monorepo 核心架构重构

## 结论

> [!success] 通过
> 两条受本次 Router/Controller 重构影响的本地 HTTP 路径均完成同机基线对比，p95/p99 未回归、错误率为 0%，吞吐变化未触发 5% 告警阈值。

## 工具检测与版本

- Apache JMeter 5.6.3，系统 PATH 可执行。
- OpenJDK 21.0.10。
- Node.js 22.22.0。
- Darwin 25.2.0 arm64，Apple M4。

## 环境与负载模型

- 目标：本机 loopback，重构前基线端口 4321，当前实现端口 4322。
- 基线：从 Git `HEAD` 导出的重构前源码，使用同一依赖锁和 Node 运行时构建。
- 数据：两个隔离的空数据目录，不读取或修改用户凭据。
- 路径：`GET /api/health`、`GET /api/ai/providers`。
- 断言：HTTP 200，并分别包含 `"ok":true`、`providerId`。
- 预热：每个版本、每条路径 5 线程 × 20 次循环，共 100 样本，不计入正式结果。
- 正式负载：10 线程、1 秒 ramp-up、每线程 100 次循环；每个版本、每条路径 1,000 样本。
- 测试顺序：基线预热与正式测试完成后，再执行当前实现；未并行施压。

## 执行证据

测试计划：`assets/features/monorepo-core-architecture/jmeter/2026-08-27-1531/health-route.jmx`

脱敏命令模型：

```bash
jmeter -n -t health-route.jmx -Jport=<port> -Jpath=<path> -Jthreads=10 -Jloops=100 -Jramp_seconds=1 -l results.jtl -j jmeter.log -e -o dashboard
```

原始 JTL、日志与从 Dashboard 保留的 `statistics.json` 位于测试计划同级的 `baseline/`、`current/` 目录。每份正式 JTL 均为 1,001 行（表头 + 1,000 样本），所有断言通过；其余可再生成的 Dashboard 静态资源未保留。

## 问题与剩余风险

- 本报告验证本地 Router/Controller 与 Provider 列表链路，不代表第三方 LLM、OAuth 或 SSE 网络性能。
- 本次没有修改 Pi AI 调用、流式迭代或 Store 算法；这些外部路径继续沿用原实现，真实供应商性能不纳入结构重构门禁。
